# Plantroom Labs — site source

Static marketing and portfolio site for **Plantroom Labs**, Niagara Framework
engineering. Generated by `build.py` into this directory and served by GitHub
Pages from `main`.

Live: <https://plantroomlabs.com/> (domain registered 2026-09-21)

## Build

```sh
python3 build.py          # rewrites every page, sitemap.xml, robots.txt, llms.txt
```

No dependencies beyond the standard library. The generator is the source of
truth: **do not hand-edit the generated HTML** — the next build overwrites it.
Edit `build.py` and rebuild.

Links are root-relative, so preview needs this directory as the document root:

```sh
python3 -m http.server 8098 -d .
# http://127.0.0.1:8098/
```

## Layout

| Path | What it is |
|---|---|
| `build.py` | the generator: page bodies, nav, JSON-LD, sitemap, `llms.txt`, demo packaging |
| `assets/css/plantroom.css` | the site design system — Layer 1 `--pl-*` tokens, Layer 2 components |
| `assets/js/site.js` | nav, FAQ disclosure, demo iframe status |
| `assets/demo/station-sim.js` | the simulated station behind every live demo |
| `assets/demo/demo-runtime.js` | minimal AMD + bajaux shim so a real widget runs unmodified |
| `assets/demo/<module>/` | widget source copied verbatim from `~/niagara/ux/nmodule/<module>/rc` |
| `img/` | still captures from the preview harness in `~/niagara/ux` |
| `brand/` | the logo kit — its own README; the site copies the badge and favicons out of it, so change geometry there, never in `build.py` |

Twelve indexed pages: `/`, `/services/` + six service pages, `/work/`,
`/faq/`, `/about/`, `/contact/`.

`/demos/{ahu,building,nav}/` are built too but carry `noindex, follow` and are
kept out of `sitemap.xml`. They are iframe targets — the widget owns the
viewport, so there is no nav, no heading and no way back; as a search result
each would be a dead end competing with `/work/`, which frames all three.

## Domain and DNS

Two constants at the top of `build.py` produce every canonical URL, `og:url`,
sitemap entry and JSON-LD `@id`, and the `CNAME` file is derived from them so
the two cannot disagree:

```python
SITE = "https://plantroomlabs.com"
BASE = ""                          # a path prefix only when served under one
```

DNS at the registrar must be:

| Type | Host | Value |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | usamaiqbal0304.github.io. |

Then in the repo's Settings → Pages: custom domain `plantroomlabs.com`, and
tick **Enforce HTTPS** once the certificate has been issued.

**`EMAIL = "info@plantroomlabs.com"` is published on every page and in the
JSON-LD.** It is an alias on the `admin@` Workspace mailbox, not a seat of
its own — Workspace bills per seat and gives aliases away, so a second
address costs nothing. Whatever it points at has to be receiving before the
site is promoted anywhere: a contact address that bounces is worse than none.

## The live demos

`/demos/*` do not show screenshots. Each runs the **actual widget JavaScript**
from `~/niagara/ux` in a sandboxed iframe, against a simulated station:

- `demo-runtime.js` provides the small slice of the bajaux contract a widget
  touches — `define`/`require`, `Widget`, `Properties`, `subscriberMixIn` — and
  a `baja` shim whose `Ord.make(...).get()` resolves `station:`, `file:`,
  `history:` and `bql:` ORDs.
- `station-sim.js` reads the widget's own config JSON, harvests every
  `station:` ORD in it, picks a behaviour model per point from its name and
  units (temperature, load, percent, CO₂, accumulator, enum…), and integrates
  them on a tick. Setpoints hold until written and then influence their
  siblings; writes from the widget go through the same path they would on a
  station. The clock is fixed at 14:20 so a 3 a.m. visitor still sees an
  occupied building.

Adding a demo for a new plugin is a `DEMOS` entry in `build.py` — module name,
widget class, config file, iframe height, widget properties. The build copies
`rc/*.js|css|json` across and inlines the JSON so `file:^module/x.json`
resolves. Nothing about the mechanism is specific to the three existing widgets.

## Honesty rules

The buyers are engineers and they check. Nothing on this site claims a client
deployment, a certification, Tridium affiliation or a Marketplace listing we do
not have. The demos are labelled as simulated stations. Keep it that way.
